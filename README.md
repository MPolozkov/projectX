# **API для Библиотеки**

## *Описание проекта:*

RESTful API для базового управления библиотечным каталогом. 
Система позволят управлять информацией о книгах и читателях, а также процессом выдачи и возврата книг, 
с использованием JWT для аутентификации пользователей (библиотекарей).

## *Содержание*
1. Создаем контейнер в Docker и создаем бд, заполняем .env файл. 
2. Создаем таблицы с помощью Alembic. 
3. Запускаем тесты.
4. Запускаем проект в браузере

## *Технологии*

1. ### **Создаем базу данных в Dockers**

   В проекте предоставлен файл `docker_compose.yal` В нем где указаны пароли написать свои (*Должны совпадать).
   Запустить команду в терминале вашего проекта `docker-compose up -d` это создаст контейнер и бд 
   внутри контейнера.


   Файл .env_sample изменить на .env и указать данные из файла docker_compose.yal:

   - `user` это `image: postgres`,
   
   - `password = "Пароль бд"` это `POSTGRES_PASSWORD: "Ваш пароль от базы данных (* должны совпадать)"`
   
   - `host = "хост на котором работает бд"(здесь пишем 4 цифры)` это `ports: "5432:5432"`
   
   Важно если вы указываете другой порт то в файле database.py, меняем вот эту строчку 
   
   `DATABASE_URL = f"postgresql://{user}:{password}@{host}/{database}"` на эту 
   `DATABASE_URL = f"postgresql://{user}:{password}@{host}:{port}/{database}"`

   добавляем порт так как по умолчанию dockers использует 5432 порт. Следовательно в файле alembic.ini, меняем 
   `sqlalchemy.url = driver://user:pass@localhost/dbname` на `sqlalchemy.url = driver://user:pass@localhost:port/dbname` 
   так же добавляем порт

   - `database = "Имя бд"` это `image: postgres`

      
2. ### ** В проекте были использованы такие зависимости как FastAPI, SQLAlchemy, Alembic Остальные зависимости
указаны в pyproject.toml. **

   - Как создать таблицы в бд, с помощью команды `alembic revision --autogenerate -m "Название миграции"` эта команда,

   создаст миграции на основе предоставленных моделей они есть в проекте, после этой команды,

   выполнить `alembic upgrade head` это создаст таблицы в бд.

3. ### ** Чтобы запустить тесты, используется библиотека pytest. **

    `pytest --cov — при активированном виртуальном окружении.`

    `poetry run pytest --cov — через poetry.`

    `pytest --cov=src --cov-report=html` — чтобы сгенерировать отчет о покрытии в HTML-формате. 
    Отчет будет сформирован в htmlcov и храниться в файле с названием index.html.

4. ### ** Чтобы запустить проект через браузер.** 

    Пишем команду `uvicorn main:app --reload,` переходим по ссылке, которую предоставит сборщик. 

    После перехода в строке браузера там где путь дописываем /docs и можно тестировать эндпоинты

    Сначала нужно пройти регистрацию потом авторизацию появится token, скопируйте его и продолжайте тест 
    следующих эндпоинтов.

5. ### ** Чтобы зарегистрировать первого пользователя (библиотекаря), можно сделать двумя способами: **

   1. Запустить тесты и все автоматически зарегистрируется.
   
   2. Запустить проект как написано выше, перейти в роутер `/register`. Перейти во вкладку "Попробуйте это", 
   выскачет окно с JSON структурой и в этой структуре указать данные для регистрации.

6. ### *** Описание принятых решений по структуре БД ***
   
   Начну с того что БД решил создать в контейнере Docker, так как при самообучении уже с этим сталкивался, 

   после создания бд решил создать 4 таблицы пользователи, книги, читатели и таблицу какой читатель взял какую книгу, 
   
   так как считаю что это удобно, потому что при получении всей этой таблицы можно сразу увидеть кто что взял и сколько.

   Да и в этой таблице я не делал зависимостей от других таблиц, потому что записываю в нее email пользователя, 

   так как по нему можно получить подробную информацию, а книгу записываю ее название так как по 

   названию могу получить подробную информацию о книге.

7. ### *** Объяснение, как реализована бизнес-логика ***

   Бизнес логика реализована таким образом когда библиотекарь регистрируется все данные заносятся в таблицу,

   далее он должен авторизоваться по своим данным по которым зарегался, выдается токен и с ним уже можно, получать 

   и удалять их, также и с книгами только книги записывать то же с токеном можно. 

   __Про пункт 4:__

   Вводится читатель и какую книгу хочет получить, проверяется токен, при помощи функции декодирования пароля, 

   делается проверка есть ли такая книга, сколько копий книги есть если книга найдена, потом проверяется сколько книг 

   у читателя, так как если 3 то больше нельзя брать. Если книгу можно выдать читателю, то в бд с книгами,

   число копий уменьшается а читатель записывается с названием книги в таблицу, если этот же читатель берет другую книгу,

   то так же записывается с другой книгой. Трудности были, это подключение к бд внутри функции и получение как 

   пользователей так и книг для начала гуг лил информацию есть наставники в школе к которым обращался этим вопросам.
